# ダーツ記録アプリ 設計書

作成日: 2026-10-27
状態: ドラフト（ユーザー承認待ち）／ビルダーチェック済み

凡例: 【ユーザー決定】はユーザーが会話で決めたこと。【Claude判断】は Claude が決めたことで、ユーザーが見直してよいもの。

---

## 1. 目的と背景

家で、みんなで、カジュアルにソフトダーツ（電子連動のない普通のボード）を遊ぶときのスコア記録アプリ。投げたら、刺さった場所を画面上で自分で選んでスコアをつける。お店のダーツマシンのように、いろいろなゲームと対戦形式を選んで対決でき、派手な演出で盛り上がれるようにする。【ユーザー決定】

同時に、ユーザー本人の**シンプルな練習用**でもある。登録プレイヤーごとに成績を残し、ゲーム別にスコアの推移・平均・最高を見返して上達を確かめたい。【ユーザー決定】

プライベート用。会社とは無関係。【ユーザー決定】

### 利用シーン
- 家で、複数人で、スマホ・タブレット・PCのうち1台をみんなで回して入力する。【ユーザー決定】
- 1人で練習するときにも使う。【ユーザー決定】

### 成功の姿
- ボードの前で迷わず、素早く、押し間違えずに入力できる。
- お店のマシンに近い盛り上がり（アワード演出・勝利演出）がある。
- 自分の成績をゲーム別に見返して、上達がわかる。

## 2. ゴール / 非ゴール / アンチゴール

### ゴール
- お店でおなじみのゲームを一通り遊べる（§5）。
- プレイヤー数を自由に増減できる。個人戦とチーム戦ができる。
- 登録プレイヤーとゲストを混ぜて遊べる。
- アワード演出・勝利演出を全部入れる。
- 登録プレイヤーの成績を保存し、ゲーム別に推移・平均・MAXを見られる。
- Chrome / Safari（PC・スマホ・タブレット）で動く。

### 非ゴール
- ダーツボードとの電子連動（Bluetooth等）。
- 複数端末間でのデータ同期、オンライン対戦、アカウント・ログイン。
- サーバー側の処理（DB・API）。
- お店の公式レーティングとの互換。

### アンチゴール（動いても失敗とみなすもの）
- スマホでトリプル/ダブルの細いリングを頻繁に押し間違える。
- 演出が長すぎてテンポが悪くなる（演出は入力で即スキップできること）。
- 入力ミスをすぐに取り消せない。
- 記録が消えてしまう（不意のリロード・タブを閉じた場合も、進行中ゲームを再開できること）。

## 3. 制約と技術方針

- **静的Webアプリ**（HTML + CSS + JavaScript）。サーバー処理なし。【Claude判断、ユーザー了承】
- **ホスティング**: GitHub Pages。個人アカウント **`taiki-iha`**（無料プラン）の**公開リポジトリ**に置き、GitHub Actions でビルド→Pages に公開する。公開URLは `https://taiki-iha.github.io/<リポジトリ名>/` になるため、サブパス配信に対応させること（ビルドのbase設定、Service Workerのスコープ）。【ユーザー決定（GitHub Pages・アカウント）／公開リポジトリはClaude判断：無料プランのPagesは公開リポジトリが必要なため】
  - PCの `gh` は現在、会社用と思われる `IharaTaiki` アカウントでログインしている。push の前に `taiki-iha` を `gh auth login` で追加し、切り替えて使う（ユーザー本人のログイン操作が必要）。
- **PWA**として「ホーム画面に追加」でアプリのように使え、一度読み込めばオフラインでも動く（Service Worker でキャッシュ）。【Claude判断】
- **データ保存**: 端末のブラウザ内（IndexedDB 推奨、少量なら localStorage も可）。端末ごとに独立。【Claude判断】
  - データ消失対策として、全データの **JSONエクスポート／インポート**（ファイル保存・読み込み）を設定画面に置く。端末を移る・機種変更する時にも使える。【Claude判断】
  - iOS Safari はホーム画面追加していない場合に長期間未使用でストレージが消える場合がある。ホーム画面追加を案内する。
- **対応ブラウザ**: Chrome、Safari の最新版（PC・iPhone・iPad・Android）。縦向きスマホを主、横向きタブレット・PCも崩れないレスポンシブ。【ユーザー決定（ブラウザ）】
- **ソースの置き場所**: `雑用\ダーツ` フォルダ。【ユーザー決定】
- 外部ライブラリは最小限。使う場合はビルドしてバンドルし、実行時にCDNへ依存しない（オフライン動作のため）。フレームワーク・ビルドツールの選定は実装者に任せる。

## 4. 画面と操作

### 4.1 画面一覧（【Claude判断】）
1. **ホーム**: ゲーム開始 / 前回の続き（進行中ゲームがあれば）/ 成績 / プレイヤー管理 / 設定
2. **ゲーム選択**: ゲームの種類を選び、ゲームごとのオプション（§5）を設定
3. **対戦設定**: 個人戦 or チーム戦、プレイヤー選択（登録プレイヤーから選択＋ゲスト追加）、投げ順、レグ数（○レグ先取）
4. **プレイ画面**: スコア表示・ダーツボード入力・3投の表示・演出
5. **リザルト**: 勝者、各プレイヤーのスタッツ、アワード回数、もう一度 / 投げ順を入れ替えてもう一度 / ホームへ
6. **成績**: 登録プレイヤーを選び、ゲーム別に推移グラフ・平均・MAX・プレイ回数・履歴一覧
7. **プレイヤー管理**: 追加・名前変更・削除（色やアイコンも選べるとよい）
8. **設定**: 効果音のON/OFFと音量、演出のON/OFF（または簡易）、ブルのセパレート/ファット既定値、データのエクスポート/インポート/全削除

### 4.2 プレイ画面の入力【ユーザー決定】
- **基本はダーツボードをクリック／タップ**して刺さった場所を選ぶ（案A）。
- スマホで細いリングを押し間違えないための工夫を入れる【Claude判断】:
  - 押している間、指の位置周辺の拡大表示（ルーペ）と、選択中のエリア名（例: `T20`）を出し、指を離した時点で確定。
  - 確定した1投は画面上の3投欄に表示され、「戻す」でいつでも取り消せる。
- ボード外は **MISS** ボタン（ボード外周タップでもMISS）。
- ボタン: `MISS` / `戻す`（1投取消。ラウンドをまたいで前のプレイヤーまで戻れる）/ `次へ`（3投未満でもラウンド終了。0点扱い）
- 3投入力した時点で自動的に次のプレイヤーへ進む（演出が終わってから、または一定時間後）。自動か手動かは設定可。【Claude判断】

### 4.3 PCのキーボード入力【ユーザー決定（Space/B/T+数字）、残りはClaude判断】
| キー | 入力 |
|---|---|
| `Space` | MISS |
| `B` | シングルブル（アウターブル） |
| `Shift+B` または `D` → `B` | ダブルブル（インナーブル） |
| 数字（1〜20） | シングル |
| `D` → 数字 | ダブル |
| `T` → 数字 | トリプル |
| `Enter` | 次のプレイヤーへ |
| `Backspace` | 1投戻す |
| `Esc` | 修飾（D/T）の取り消し、演出のスキップ |

- 2桁の数字（10〜20）の扱い: `1` を押した後に短い待ち時間（例 0.6秒）で次の数字を受け付け、来なければ「1」で確定。`Enter` で即確定も可。実装者は誤入力が起きにくい方式を選んでよい。
- シングルのインナー/アウターは区別しない（点数が同じため）。

### 4.4 ブルの扱い
- ゲーム設定で **セパレート**（アウター25 / インナー50）と **ファット**（どちらも50）を選べる。既定はファット（多くのお店の01の既定に合わせる）。【Claude判断】
- クリケットではアウターブル=1マーク、インナーブル=2マーク。

## 5. ゲーム一覧

【ユーザー決定】01系、クリケット、カウントアップを含め「お店でおなじみのゲームはなるべく全部」。以下の一覧は【Claude判断】。ルールの細部はお店（DARTSLIVE / PHOENIX）の一般的なルールに合わせる。

### 5.1 01系（ゼロワン）
- 持ち点: 301 / 501 / 701 / 901 / 1101 / 1501
- ちょうど0にしたら上がり。超えたら**バースト**（そのラウンドの得点は無効、ラウンド開始時の点数に戻る）。
- オプション: IN（オープン / ダブル / マスター）、OUT（オープン / ダブル / マスター）、ブル（セパレート / ファット）、ラウンド上限（既定: 301は10、501は15、701以上は20。上限到達時は残り点が少ない方が勝ち）
- チーム戦では持ち点をチームで共有。
- 上がり目アシスト: 残り点数が170以下になったら、上がりの例（例: `T20 T20 DB`）を表示（OUT設定に応じる）。【Claude判断】

### 5.2 クリケット系
- 対象: 15〜20とブル。シングル=1、ダブル=2、トリプル=3マーク。3マークでオープン。
- **スタンダードクリケット**: 自分がオープンし相手がオープンしていない数字に入れると加点。全てオープンかつ点数が上回れば（同点含む規則はお店準拠）勝ち。ラウンド上限15〜20。
- **カットスロートクリケット**: 加点が相手側に入り、点数が少ない方が勝ち（3人以上向き）。
- **ヒドゥンクリケット**: 対象ナンバーがランダム（ゲーム中に判明）。
- 盤面表示: お店と同じ「／ × ⊗」マーク表で全員の状況を一覧。

### 5.3 練習・パーティ系
- **カウントアップ**: 8ラウンドの合計点を競う（ブルはファット）。
- **クリケットカウントアップ**: 8ラウンド、クリケットナンバーへのマーク数を点数化。
- **ハーフイット**: ラウンドごとに指定エリア（例: 15/16/D/17/18/T/19/20/BULL）を狙い、1本も入らなければ持ち点が半分。
- **ローテーション（アラウンド・ザ・クロック）**: 1から20、ブルまで順に当てていく。最短ダーツ数を競う。
- **シャンハイ**: ラウンドnでナンバーnを狙う。同ラウンドでS・D・Tを揃えると即勝利。
- **イーグルアイ**: ブルだけを狙う8ラウンド（インナー/アウター区別の得点）。
- **ビッグブル**: ブル狙いの点数ゲーム。

実装の優先順位: 01系 → スタンダードクリケット → カウントアップ → 残り。ゲームは**後から追加しやすい構造**（ゲームごとのルールを1つのモジュールに閉じる）にすること。

**段階リリース【Claude判断】**
- **第1弾**（これで一度使える状態にする）: 01系・スタンダードクリケット・カウントアップ、個人戦／チーム戦／レグ制、全アワード演出（該当ゲーム分）、登録プレイヤー・ゲスト、成績画面、進行中ゲームの再開、PWA化、エクスポート／インポート。
- **第2弾**: カットスロート・ヒドゥンクリケット、クリケットカウントアップ、ハーフイット、ローテーション、シャンハイ、イーグルアイ、ビッグブル。
- 第2弾のゲームを足してもデータ形式（全投記録）を変えずに済むよう、第1弾の時点で汎用的に設計する。

## 6. 対戦形式

- **個人戦**: 1人〜（上限は8人程度。実装者判断で増やしてよい）。1人なら練習（ソロ）。【ユーザー決定（任意人数）】
- **チーム戦**: 2チーム以上。チームで1つのスコアを共有し、メンバーが交代で投げる（例: A1 → B1 → A2 → B2 → A1…）。人数の違うチーム同士（2対3など）も可。【ユーザー決定（交代で投げる）】
- **レグ制**: 「○レグ先取」を選べる（既定: 1レグ）。レグごとに先攻を交代。【Claude判断】
- 投げ順: 手動並べ替え、ランダム（コルク＝ブル近い順は入力が面倒なので省略）。【Claude判断】

## 7. 演出

【ユーザー決定】ブル、ホワイトホースなど一般的なアワード演出は全部入れる。見た目は派手でかっこよく、**A. ネオン・サイバー**（暗い背景に青・ピンクの発光）。

### 7.1 アワード一覧（【Claude判断】、お店の一般的なものに準拠）
| アワード | 条件 |
|---|---|
| LOW TON | 1ラウンド 100〜150点（01系・カウントアップ） |
| HIGH TON | 1ラウンド 151〜179点 |
| TON 80 | T20×3（180点） |
| HAT TRICK | 1ラウンドでブル3本 |
| THREE IN A BED | 同じエリア（同じ数字・同じ倍率）に3本 |
| THREE IN THE BLACK | インナーブル3本 |
| WHITE HORSE | クリケットで、異なるクリケットナンバーのトリプル3本（未オープン数字） |
| 5〜9 MARKS | クリケットの1ラウンドのマーク数 |
| BULL | ブル1本ごとの小演出 |
| GAME SHOT / WIN | 上がり・勝利 |
| BUST | バースト |

- 01系の点数系アワードとブル系が同時に成立する場合は、上位の1つ（例: HAT TRICK）を大きく出す。【Claude判断】

### 7.2 演出の作り
- ネオン調のアニメーション（光が走る・揺れる・グロー）。大きな文字＋背景エフェクト。ブル1本などの小演出は短く、TON 80・ホワイトホース・勝利は大きく。【ユーザー決定（方向性）／詳細はClaude判断】
- **効果音はブラウザ内で合成**（Web Audio API）。お店の音源は使わない。【Claude判断】
- 演出は画面タップ／`Esc`／次の入力で即スキップ可能（アンチゴール対策）。
- 設定で演出・効果音をOFFにできる。
- iOS Safari は最初のユーザー操作まで音が鳴らないため、ゲーム開始ボタンで音声を有効化する。

### 7.3 見た目
- 暗い紫〜黒の背景、シアン（#00e5ff 系）とマゼンタ（#ff2bd6 系）の発光。手番のプレイヤーをグローで強調。
- ダーツボードもネオン配色（ブラウザのモックアップで合意したもの）。モックアップのHTMLは `雑用\ダーツ\.superpowers\brainstorm\` に残っている。

## 8. プレイヤーと成績

### 8.1 プレイヤー【ユーザー決定】
- 登録プレイヤーを作っておき、対戦設定で選ぶ。その人の記録が保存される。
- **ゲスト**も参加できる。ゲストの記録は成績に残さない（その試合の履歴には残る）。【ゲストの成績扱いはClaude判断】

### 8.2 保存するデータ【Claude判断】
- 試合単位: 日時、ゲーム種別とオプション、対戦形式、参加者（チーム構成）、勝者、**全投の記録**（誰が・何ラウンド目・何投目・どこに刺さったか）。
  - 全投を残しておけば、後から新しい統計を追加しても過去データから計算できる。
- 進行中のゲームは1投ごとに保存し、リロード・タブを閉じても再開できる。

### 8.3 成績画面【ユーザー決定（ゲーム別の推移・平均・MAX）】
- プレイヤーを選び、ゲーム別（01はオプション違いも区別できるように）に:
  - スコアの**推移グラフ**（直近N試合 / 期間指定）
  - **平均**、**MAX（自己ベスト）**、プレイ回数、勝率
- ゲーム別の主な指標【Claude判断】:
  - 01系: PPD（1ダーツあたり平均点）、上がりまでのダーツ数
  - クリケット: MPR（1ラウンドあたり平均マーク）
  - カウントアップ: 合計点
  - その他: ゲーム固有のスコア
- アワードの累計回数（TON 80 何回、など）。
- チーム戦の個人スタッツも、その人が投げた分は個人の成績に含める。【Claude判断】

## 9. 実装者に任せること
- フレームワーク・ビルドツール・状態管理の選定。
- 画面遷移とレイアウトの細部、アニメーションの具体的な作り。
- 2桁数字キー入力の確定方式の詳細。
- 各ゲームの細かいルール差（お店ごとに違う部分）は一般的な方に合わせる。迷ったものは設定画面にオプションとして出してよい。
- テストの方針（ゲームのルール・スコア計算・アワード判定は自動テスト必須）。
